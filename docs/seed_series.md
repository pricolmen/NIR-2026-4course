# Воспроизводимые серии на нескольких seed

Обёртка [run_seed_series.py](../tools/run_seed_series.py) организует существующие команды C++-стенда. Она не реализует моделирование, RNG или расчёт метрик: отдельные входы создаёт generate, четыре сочетания сравнивает batch. Зависимости обёртки — Python ≥3.9 со стандартной библиотекой; исполняемая программа задаётся явно. Git используется для доступных сведений о версии, его отсутствие фиксируется в manifest.

Это инфраструктура этапа 1 новой очереди экспериментов. Пробные два seed проверяют организацию; их результаты не используются для выводов о превосходстве алгоритмов. Формулы fixed/adaptive, время, фазы, FAILED и определения метрик сохранены.

## Сборка и пробный запуск

Из корня проекта, при доступных CMake/Ninja и сети для первой загрузки JSON:

```sh
cmake -G Ninja -S . -B build/experiment-stage1-release -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build build/experiment-stage1-release --parallel 4
ctest --test-dir build/experiment-stage1-release --output-on-failure

python3 tools/run_seed_series.py --template examples/generator.json --seeds 101 202 --program ./build/experiment-stage1-release/telemetry_sim --out results/experiment-stage1-seeds
```

Для автономной настройки добавьте `-DFETCHCONTENT_SOURCE_DIR_NLOHMANN_JSON="$PWD/build/debug/_deps/nlohmann_json-src"`, если проверенная зависимость уже сохранена там. Установка/другие пути описаны в [README](../README.md). Можно использовать другой собранный telemetry_sim, явно указав путь в --program. Сведения о реально выполненной сборке и проверках: [отчёт этапа 1](experiment_stage_1_audit.md).

Шаблон examples/generator.json существовал до этого этапа. В нём случайная работа 1..4, задержка 0..3 тика и вероятность потери 0.15. Конфигурация каждой реализации отличается от шаблона только заданным seed. Исходный шаблон копируется без изменения байтов, его SHA-256 сохраняется. Никакие параметры не выбираются скриптом случайно или скрыто.

Обязательные аргументы режима генерации: --template, --seeds, --program, --out. Seed — явные различные целые uint64, включая 0; диапазоны seed и автоматический выбор не добавлены. Необязательный --scenario-id задаёт метку группировки batch; по умолчанию используется имя файла шаблона без расширения. --source-dir позволяет явно указать каталог исходников для записи происхождения сборки; по умолчанию это корень проекта со скриптом.

## Состав каталога серии

| Путь | Назначение |
|---|---|
| template.json | Точная копия исходного шаблона в режиме генерации |
| configs/seed_101.json | Конкретная конфигурация generate; меняется только seed |
| inputs/seed_101/ | Полностью сохранённый результат generate: scenario.json, delivery.csv, generator_config.json, generation_manifest.json |
| batch_input.json | Manifest фактического CLI: schema_version=1 и runs с scenario_id/repeat_id/scenario |
| batch/batch_manifest.json | Реальные соответствия меток и runs/000001, runs/000002, … |
| batch/runs/000001/ | Четыре полных запуска fixed_rr/fixed_ll/adaptive_rr/adaptive_ll |
| batch/comparison.csv, batch/summary.csv | Исходные отчёты существующего batch, без нового расчёта статистики в Python |
| series_manifest.json | Статус серии, seed, входы/хеши, команды/коды выхода, пути результатов, происхождение |
| logs/ | Отдельные stdout/stderr каждого вызова CLI, в порядке исполнения |

Метки repeat_id имеют вид seed_00000000000000000101. Batch сортирует метки; порядок каталогов не выводится из порядка введённых seed. Скрипт читает фактический batch_manifest.json и сохраняет batch_output для каждого seed. Входные и выходные пути внутри manifest серии относительные, их можно переносить вместе с каталогом.

Для каждого повтора проверяется complete и наличие ровно четырёх вариантов. SHA-256 обоих сохранённых входов сверяется с общим снимком сравнения и input/* каждого варианта. Совпадение seed само по себе не считается достаточной проверкой. Дополнительно фиксируются хеши журнала и производных результатов.

## Повторное исполнение сохранённых входов

```sh
python3 tools/run_seed_series.py --reuse-series results/experiment-stage1-seeds --program ./build/experiment-stage1-release/telemetry_sim --out results/experiment-stage1-replay
```

Режим --reuse-series принимает каталог ранее завершённой серии этой обёртки. Он проверяет manifest и хеши, копирует scenario.json/delivery.csv без изменения байтов и вызывает только batch, без generate. Seed и метки сохраняются. Для такой работы нужны manifest, сохранённые входы и указанные в нём конфигурации/метаданные генерации; старые журналы не перечитываются.

В provenance/ сохраняются сведения первоначальной генерации и исходный manifest серии. Копии generation_manifest описывают первоначальное создание входа, а не новую генерацию. Новая серия имеет mode=reused и собственные сведения о программе/командах.

На том же исполняемом файле автоматически сверяются содержательные результаты каждого варианта: events.jsonl, metrics.json, tasks.csv, attempts.csv, nodes.csv. Manifest запусков не сравнивается побитово: происхождение и пути могут закономерно различаться. При другом бинарнике равенство результатов записывается как наблюдение, но не навязывается; переносимость вещественных расчётов разных сред не гарантируется.

Такое исполнение проверяет воспроизводимость. Оно не является новым независимым повтором и не увеличивает научную выборку: native batch получает только реализации текущей серии, исходная и повторная серии не объединяются.

Произвольные готовые сценарии без manifest этой обёртки по-прежнему можно сравнивать существующим batch, задав обычный manifest по [CLI-контракту](cli.md). Обёртка не пытается угадывать seed такого входа.

## Явная замена параметров при сохранённых задачах и доставке

Для будущих этапов предусмотрен --detector-overrides FILE только вместе с --reuse-series. Пример содержимого файла (это описание интерфейса, не проведённая исследовательская серия):

```json
{"tau0_ticks":30000,"kappa":2,"adaptive":{"c":2,"window":3,"min_intervals":2}}
```

Разрешены только tau0_ticks, kappa и отдельные поля adaptive: c, window, min_intervals. Неуказанные поля сохраняются. Добавлять alpha, новую формулу, менять задачи, H, узлы, crash/blackout или условия доставки этим интерфейсом нельзя. Представимость и допустимость значений проверяет существующий CLI при чтении batch. Числа читаются через Decimal и сохраняются JSON-числами без сужения исходной работы до Python float.

В таком запуске scenario.json явно меняется по перечисленным параметрам; исходная версия сохраняется в provenance/seed_*/source_scenario.json, патч — в detector_overrides.json, изменения — в manifest. Задачи проверяются на точное совпадение значений, delivery.csv — на совпадение байтов. Генерация отсутствует. Manifest первоначальной генерации хранится отдельно и не выдаётся за описание изменённых параметров. Повтор на изменённых параметрах не обязан давать старые результаты.

## Происхождение и ошибки

Сохраняются --build-info, SHA-256 бинарника и самого скрипта, Python/платформа, git commit/status/хеш diff и снимок хешей CMake/app/include/src, если исходники доступны. Бинарник не содержит встроенной привязки к git commit: запись каталога исходников сама по себе не доказывает, из какого commit собран произвольный --program. Для проверенной сборки этапа команда сборки и лог приведены в отчёте.

Статус становится complete только после успеха batch и проверок. При ошибке остаются status=failed и логи; это не успешная серия. Ненулевой выход CLI не игнорируется. Числа с повторяющимися JSON-ключами и NaN/Infinity отклоняются обёрткой; семантику параметров проверяет C++ CLI.

--out обязан быть новым, даже если существующий каталог пуст. Перезапись и --overwrite не добавлены. Каталог повторной серии не должен находиться внутри исходной серии. Параллельное изменение входов/бинарника во время запуска не поддерживается; их контрольные суммы дополнительно проверяются до завершения.

Разные seed задают отдельные псевдослучайные реализации в одной программной среде. Совпадения возможны, особенно при постоянных диапазонах; число различных фактических входов сохраняется и при совпадении печатается пояснение. Это не математическое доказательство независимости. Для этапа 1 показаны только организация двух реализаций и их технический повтор. Сводки с доверительными интервалами, графики и план исследования параметров относятся к следующим поручениям.

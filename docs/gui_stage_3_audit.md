# GUI КР Этап 3 Создание и сохранение сценариев

Дата: 2026-11-16. Этап 3 завершён до перехода к итоговой проверке этапа 4, разрешённой последним сообщением пользователя. КР/DOCX и расчётные исходники не редактировались.

Добавлены gui/scenario_files.hpp/cpp, scenario_dialogs.hpp/cpp, tests/editor_tests.cpp; расширен RunController для generate и проверки копии, MainWindow для формы/редактора, CMake и инструкция. [Сборка и работа](../gui/README.md).

Форма задаёт состав/производительность, горизонт/поток задач/трудоёмкость, heartbeat/диапазон задержек/потери/перерывы, T₀/κ/M/min_intervals/c и seed. Время — целые мкс, ID/seed — uint64 без double. Стандартное окно throughput занимает весь горизонт. Перед расчётом записывается конфигурация, отдельным процессом исполняется native generate, затем прежний validate → run. Random/RNG, детектор, планировщик и метрики не реализовывались заново.

Редактор готового сценария допускает пустой список, несколько узлов и одинаковые моменты; проверяет известность/единственность узла и 0 ≤ момент ≤ горизонт. Правятся только диапазоны значений crashes и delivery_trace в исходных байтах JSON. Полный синтаксис разбирает библиотека nlohmann/json; узкий сканер находит границы двух значений, не валидирует формат сценария. Точность задач/прочих чисел и их исходная запись сохраняются. CSV копируется побитово под новым именем в каталог JSON. Временная пара проходит native validate до публикации. Оригиналы и существующий целевой файл/символьная ссылка не заменяются; проверяются SHA входов и подготовленных данных. При аварии между двумя публикациями возможен отдельный CSV, общей транзакции двух файлов нет.

# Статистический анализ сохранённых серий

Этап 8 новой очереди экспериментов читает завершённые основные серии этапов 2–7. Он не запускает generate/run/batch/metrics и не меняет C++-модель, входы, журналы, формулы детекторов или определения native-метрик. [План](../experiments/statistics_stage8/plan.json), [инструкция](../experiments/statistics_stage8/README.md), [аудит](experiment_stage_8_audit.md).

## Источники и единица наблюдения

В плане явно указаны network/timeout/kappa/coefficient/window/load: шесть основных каталогов, 180 ячеек и 7200 выполнений вариантов. В каждой ячейке четыре варианта на десяти seed. Replays, демонстрация этапа 1, старые материалы главы 4 и произвольные соседние каталоги не подхватываются автоматически.

Единица статистического анализа — показатель одного полного запуска на одном seed. Нельзя выдавать 40/120 задач, два/четыре узла, четыре алгоритма, связанные значения параметра и повторное чтение трассы за дополнительные независимые seed. Сводка отдельно группируется по series/case/variant/metric. Между разными этапами наблюдения не объединяются даже при одинаковых параметрах/seed. Разные номера seed задают отдельные псевдослучайные реализации, но не являются математическим доказательством независимости.

Импорт читает исходные manifests, сохранённые входы, metrics.json и native comparison.csv. Проверяются complete, seed→repeat_id→batch_output, дубли, единицы, балансы, входы четырёх вариантов, SHA-256 обоих входов и пяти содержательных файлов каждого варианта. Значения/причины пропусков сравниваются с native CSV. Целые счётчики сравниваются точно, вещественные записи JSON/CSV — с rel_tol=1e−12, abs_tol=1e−9 только из-за различий десятичного представления. Это не пересчёт метрик по событиям: их определения остаются в C++.

План выбирает window_index=0. Общие latency/счётчики встречаются в native CSV для каждого окна, поэтому они импортируются ровно один раз. Throughput берётся из выбранного окна; границы сохраняются и проверяются в группах/парах. Ни окна, ни повторённые totals не суммируются.

## Показатели

В observations.csv сохраняются native mean latency, P95, Detection, Recovery (с переводом микросекунд в миллисекунды), throughput (задач/с), completed/unfinished, FP/FN/Late, incomplete_recoveries и retries. Вместе с ними записываются размеры native latency/detection/recovery, число задач/узлов, границы окна, причины пропусков и хеши входов.

Latency относится только к завершённым задачам внутри запуска. P95 — уже вычисленный native ближайший ранг внутри запуска; статистический анализ оценивает среднее этих P95 по seed, а не объединённый P95 всех задач. Завершённость/незавершённость нужно рассматривать рядом с задержками: низкая latency оставшейся малой части не означает хорошего обслуживания потока.

FP — ложное исключение узла, FN — необнаруженный физический crash по текущей классификации; Late — crash после прежнего FP. FN=0 при Late>0 не гарантирует правильного обнаружения. Detection определяется только для корректных обнаружений. Recovery — завершение фиксированного возвращённого набора, а не всех задач; незавершённый Recovery остаётся неопределённым.

## Средние и интервалы

Для каждого показателя выводятся n_expected, n_defined, n_missing, среднее, выборочное SD (делитель n−1), минимум/максимум и интервал среднего. Отсутствующее native-значение не заменяется нулём. При n=0 нет среднего/SD/интервала; при n=1 есть среднее, но нет SD/интервала.

План заранее задаёт bootstrap_seed=20261109, 20000 resamples, confidence_level=0.95. В каждой повторной выборке с возвращением выбираются целые seed из доступных определённых наблюдений, вычисляется среднее, а границы берутся как квантили 2.5%/97.5% с линейной интерполяцией. Используется percentile bootstrap, не BCa. Методический источник: [SciPy bootstrap, раздел percentile и paired](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html), [NIST о paired bootstrap](https://www.itl.nist.gov/div898/software/dataplot/refman1/auxillar/bootplot.htm).

Индексы генерируются NumPy PCG64 из фиксированного seed и SHA-256 упорядоченного списка доступных seed. Один и тот же список seed использует одни индексы во всех показателях/условиях. Порядок чтения файлов или наблюдений не меняет результат. Bootstrap не моделирует новые физические трассы и не увеличивает научный объём выборки.

Интервалы Detection/Recovery условны на доступные значения. Если n_defined меньше десяти, они не оценивают среднюю задержку всех физических отказов; никакой коррекции цензуры не выполняется. При десяти seed bootstrap может плохо описывать хвосты. Постоянная выборка даёт вырожденный эмпирический интервал: [0;0] для FP означает отсутствие вариации наблюдённых seed, а не доказанный нулевой риск в генеральной совокупности.

Все интервалы pointwise: поправки на множество сравнений и одновременного покрытия кривых нет. P-values, выбор универсального победителя, точное номинальное покрытие и статистическая значимость по пересечению отдельных интервалов не заявляются.

## Парные различия

В contrasts.csv направление всегда **left−right**. Для каждого seed сначала вычитаются соответствующие значения, затем bootstrap выполняется по этим разностям как по целым парам. Это не разность двух независимо рассчитанных средних и не независимый resampling сторон. В paired_observations.csv видны обе стороны, пропуск и разность.

Включены:

- Внутри каждой ячейки: adaptive_rr−fixed_rr, adaptive_ll−fixed_ll, fixed_ll−fixed_rr, adaptive_ll−adaptive_rr. Полные входы сторон должны совпадать.
- Изменение параметров относительно исходных уровней: T₀=20 мс, κ=2, c=2, M=3; каждый вариант сравнивается сам с собой на том же seed/профиле. Трасса совпадает, scenario отличается только указанным параметром.
- В четырёхузловой серии: heterogeneous−equal при одинаковой интенсивности/связи/режиме и уровни интенсивности относительно moderate при одинаковой производительности/связи/режиме. Проверяется совпадение работ и трасс; разрешённые различия — только nodes либо arrival_ticks соответственно.

Опорные уровни заданы до анализа, а не выбраны по минимальным значениям результата. Между разными сериями парные сравнения не создаются. Сеть показана полными поячеечными сводками/интервалами; отдельные парные различия jitter/q здесь не вычисляются.

Для пары используются только seed, где обе стороны определены. Записываются n_left_defined, n_right_defined и число полных пар n_defined; размеры могут различаться. Такая разность условна на пересечение доступных seed и не исправляет селекцию от ранних FP/незавершённых Recovery. Отсутствие записи seed считается ошибкой, а не пропуском метрики.

T₀ влияет также на прогрев adaptive. κ действует в обоих детекторах. c/M не меняют fixed, но M меняет диагностические записи истории даже при чистой связи. В четырёхузловой модели heartbeat не замедляются от вычислительной нагрузки; её влияние на задержку обнаружения не заявляется. Ограничения исходных этапов сохраняются.

## Графики и воспроизводимость

Matplotlib Agg создаёт 34 самостоятельные фигуры, каждая в PNG и SVG: две по сети; по шесть для T₀/κ/c/M (три связи × healthy/crash); шесть по нагрузке; две с парными LL−RR для clean. figure_data.csv содержит точные отображённые средние, границы и n. Где оценки детектора совпадают для RR/LL, отображается одна линия на детектор после проверки равенства.

Неполные n показываются в таблице справа от соответствующей панели в порядке x. При n=0 линия прерывается: точка в нуле не рисуется. Вырожденность интервалов оговорена в подписях. Для latency/P95/Recovery показаны отдельные RR/LL; графики разностей явно указывают LL−RR. Поля текста проверяются на выход за границы canvas, все графики проходят визуальный контроль.

Код анализа находится в tools/run_statistics.py и tools/telemetry_stats/. NumPy/Matplotlib относятся только к Python-анализу; обычные C++-сборка и 93 CTest их не требуют. Опция TELEMETRY_ENABLE_STATISTICS_TESTS добавляет одну группу из семи Python unittest (94 CTest в проверенной конфигурации). Закреплённое окружение проверено на Python 3.14/macOS arm64; другие Python/платформы здесь не удостоверены.

Источники повторно сверяются по хешам после анализа. Сохраняются версии Python/библиотек, настройки, хеши кода/источников/артефактов. В одной среде проверяется точный повтор CSV/PNG/SVG; служебный manifest не сравнивается из-за пути --out. PNG/SVG не содержат текущую дату. Исходные журналы и результаты не перезаписываются; выход обязан быть новым.

# Ручной пример: crash

Два узла, четыре задачи в 0, H=5, tau0=10, kappa=2, горизонт 40. Узел 1 физически падает в 3. Трасса содержит и потенциальные отправки после crash, одинаковые для всех вариантов. На этапе 10 работа узла 1 останавливается в 3, а ядро узнаёт об отказе только через тайм-ауты: SUSPECT в 10, FAILED в 20. Fixed/adaptive RR возвращает задачи 1 и 3 в 20 на узел 2 и получает завершения по ID [24,2,28,4]. Эти значения проверяются integration_crash; метрики ещё не вычисляются.

Это проверочный сценарий, а не доказательство преимущества алгоритма. Все времена — целые микросекундные тики.
